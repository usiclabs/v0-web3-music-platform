2. CORE FEATURES (6 Main Pillars)
───────────────────────────────────────────────────────────────────────────────

A) X402 MICROPAYMENTS (Core Revenue)
   - Pay-per-30-second-chunk in USDC on Base
   - Listeners pay before chunk unlocks
   - Automatic royalty distribution per splits
   - On-chain verification → next chunk released

B) ARTISTS & CONTENT
   - Upload tracks with cover art, title, duration, pricing
   - Dashboard: manage content, real-time earnings, analytics
   - Profile tokenization (create ERC-20 artist token)
   - Token-gating (require token balance to stream)
   - Royalty split configuration
   - NFT minting per track (ERC-1155 with immutable royalties)

C) LISTENERS & DISCOVERY
   - /discover (curated) → /explore (search) → /trending (real-time)
   - Follow artists, like/comment/create playlists
   - Token-gated content access
   - Activity feed, search history
   - Listen tracking for personalization

D) AI AGENTS (Autonomous System)
   → 1) Autonomous Artist Agent: Auto-generates music via Suno AI, auto-publishes
   → 2) Auto-Stream Agent: Bot wallet streams music autonomously, pays for streams
   → 3) Market-Maker Agent: DEX trading bot (Burst/Pro/Fomo/Max modes)
   → 4) Investment Agent: Auto-buys artist tokens based on strategy
   → 5) Token Sniper Agent: Auto-buys tokens matching criteria
   → 6) Custom Eliza Agents: Extensible framework for custom behaviors
   All agents have encrypted wallets, activity logging, portfolio tracking

E) PREDICTION MARKETS
   - Create markets on artist/track metrics
   - Binary YES/NO betting with odds
   - Real-time resolution on target dates
   - PnL tracking per position
   - Database tracks all trades/positions/payouts

F) ADDITIONAL FEATURES
   - Live streaming (Livepeer integration)
   - Staking (lock tokens for rewards)
   - Token swaps (Uniswap V3 integration)
   - NFT marketplace (mint, list, trade, bid)
   - Stories (24-hour ephemeral content, token-gated optional)
   - Referral system with leaderboard
   - Builder program codes for marketing
   - Airdrop claims

10. KEY WORKFLOWS & DATA FLOWS
───────────────────────────────────────────────────────────────────────────────

ARTIST PUBLISHING:
  1. Artist uploads track via /dashboard/upload (audio + metadata)
  2. File stored in Vercel Blob, metadata in DB (tracks table)
  3. Set price, royalty splits, token-gating (if applicable)
  4. Track appears on /discover after admin approval (optional)
  5. Artist sees real-time earnings in /dashboard/earnings

LISTENER STREAMING:
  1. Listener discovers track on /discover or /explore
  2. Initiates play via audio player
  3. Every 30 seconds: X402 payment prompt
  4. User approves USDC transaction in wallet
  5. Smart contract verifies payment on Base
  6. Next 30-sec chunk unlocked & streamed
  7. Royalties auto-distributed to splits
  8. Stream event logged in streams table

AUTONOMOUS ARTIST AGENT:
  1. Artist creates agent via /dashboard/agent/autonomous-artist
  2. Configure: daily budget, generation frequency, genre/style
  3. Agent wakes daily/hourly, calls Suno AI API
  4. Suno generates track (5-30 minutes)
  5. Webhook returns audio URL + metadata
  6. Agent uploads to platform automatically
  7. Track published under artist name
  8. Earnings tracked in autonomous_artist_activity table

AUTO-STREAM AGENT:
  1. User creates agent with budget & target genres/artists
  2. Agent autonomously streams music (plays 30-sec chunks)
  3. Pays USDC for each chunk (via agent wallet)
  4. Streams logged in streams table
  5. Artists receive royalties in real-time
  6. Agent tracks total spend & stream count

MARKET-MAKER AGENT:
  1. User deploys MM agent with wallet funding
  2. Detects liquidity pools via /api/agents/mm/v4-support/pools
  3. Executes buy/sell pairs based on mode (Burst, Pro, Fomo, Max)
  4. Tracks portfolio in agent_portfolio table
  5. Calculates PnL continuously
  6. User monitors via /agents/[address]

PREDICTION MARKET:
  1. Create market on /predictions/create (e.g., "Will artist XYZ reach 1M streams?")
  2. Set resolution date & criteria
  3. Users place YES/NO bets
  4. Real-time odds calculated from order flow
  5. On resolution date, market resolved (admin/oracle)
  6. Winners receive payout, losers lose bet amount
  7. History in prediction_payouts table
